# Щотижнева статистика — Google Sheets → GitHub Pages

Готовий статичний сайт у дизайні 1440×812 з окремим фоном, e-Ukraine, автоматичним тижневим діапазоном **понеділок–неділя**, даними з Google Sheets та кнопкою експорту поточного екрана в PNG.

## 1. Як підготувати нову Google-таблицю

Створіть нову Google Spreadsheet і додайте аркуш з назвою **SiteData**.

У першому рядку зробіть колонки саме в такому порядку/з такими назвами:

| week_start | week_end | metric_id | label | percent | answer | sort_order |
|---|---|---|---|---:|---|---:|
| 2026-08-24 | 2026-08-30 | experience | Досвід керування дроном респондентів | 40 | Є певний досвід, більше 10 годин | 1 |

### Що означає кожна колонка

- `week_start` — понеділок тижня у форматі `YYYY-MM-DD`.
- `week_end` — неділя того самого тижня.
- `metric_id` — стабільний ID блоку. Для одного блоку всі варіанти відповіді мають один і той самий `metric_id`.
- `label` — заголовок статистичного блоку.
- `percent` — відсоток конкретної відповіді.
- `answer` — текст відповіді, яка відповідає цьому відсотку.
- `sort_order` — порядок 1–7 на сайті.

**Важливо:** сайт сам вибирає найбільший `percent` всередині кожного `metric_id` і бере `answer` з того самого рядка. Тобто якщо для питання є 5 варіантів відповідей, у таблиці буде 5 рядків з однаковим `metric_id`, а на сайті покажеться лише найбільший.

## 2. Як тягнути дані з основної таблиці у SiteData

Якщо відповіді форми вже знаходяться в іншій Google-таблиці, найзручніше залишити RAW-таблицю окремо, а `SiteData` використовувати як підготовлений шар для сайту.

### Варіант A — IMPORTRANGE

У новій таблиці створіть аркуш `RAW` і використайте:

```text
=IMPORTRANGE("URL_ВАШОЇ_ОСНОВНОЇ_ТАБЛИЦІ";"RAW!A:Z")
```

При першому використанні Google Sheets попросить **Дозволити доступ**.

Після цього на `SiteData` формуйте потрібні рядки з RAW через `QUERY`, `FILTER`, `SORT`, `UNIQUE` або окремі формули.

### Варіант B — Google Apps Script

Якщо логіка підрахунку складна (наприклад, Google Forms зберігає кілька відповідей в одному полі), краще один раз написати Apps Script, який:

1. читає RAW-відповіді;
2. групує відповіді за питаннями;
3. рахує кількість кожного варіанта;
4. переводить кількість у відсоток;
5. записує результат у `SiteData`;
6. запускається автоматично раз на тиждень.

У репозиторії є готовий шаблон структури даних, але назви питань у вашій формі треба прив'язати до реальних колонок RAW.

## 3. Відкрити таблицю для GitHub Pages

Для простого статичного сайту найнадійніший варіант — опублікувати **тільки SiteData** як CSV.

У Google Sheets:

**Файл → Поділитися → Опублікувати в Інтернеті → вибрати SiteData → CSV → Опублікувати.**

Скопіюйте URL CSV.

> Якщо дані містять приватну/чутливу інформацію, не публікуйте всю таблицю. `SiteData` має містити тільки ті агреговані дані, які можна відкрито показувати на сайті.

## 4. Підключити CSV до сайту

Відкрийте `config.js` і вставте URL у:

```js
window.SITE_CONFIG = {
  CSV_URL: 'https://docs.google.com/spreadsheets/d/ВАШ_ID/export?format=csv&gid=ВАШ_GID',
  ...
};
```

У готовому архіві `CSV_URL` порожній, тому сайт показує demo-дані. Після вставлення URL сайт братиме дані з Google Sheets.

## 5. Як працює автоматичний тиждень

Сайт при кожному відкритті визначає поточний тиждень:

- понеділок = початок;
- неділя = кінець.

Наприклад, для 31 серпня 2026 року буде показано **31 серпня – 6 вересня 2026**.

Якщо в таблиці ще немає нового тижня, сайт автоматично бере **останній доступний тиждень**, щоб сторінка не залишалась порожньою.

Тому сам сайт не потрібно редагувати щотижня.

## 6. Як працює кнопка «Копіювати дані»

Кнопка фактично створює PNG-знімок сторінки **в момент кліку**:

- бере актуальні дані, які зараз відображені;
- зберігає фон і весь дизайн;
- експортує PNG у високій роздільності;
- назва файлу містить діапазон поточного тижня.

## 7. Залити на GitHub Pages

1. Створіть новий GitHub repository.
2. Завантажте **вміст папки архіву**, а не саму папку всередині іншої папки.
3. У репозиторії відкрийте **Settings → Pages**.
4. У Source виберіть **Deploy from a branch**.
5. Branch: `main`, folder: `/ (root)`.
6. Натисніть Save.
7. Відкрийте URL GitHub Pages.

## 9. Що змінювати не потрібно

Не потрібно щотижня змінювати:

- HTML;
- CSS;
- фон;
- дати в коді;
- відсотки;
- відповіді;
- PNG-кнопку.

Зміни відбуваються через Google Sheets.

## 10. Важлива примітка про шрифт

Сайт підключає e-Ukraine як webfont. Офіційна сторінка Міністерства цифрової трансформації містить актуальну гарнітуру e-Ukraine та окремо e-Ukraine Head. Для цього дизайну використовується основний e-Ukraine.

Якщо потрібна повністю автономна версія без зовнішнього webfont CDN, завантажте офіційний пакет e-Ukraine і покладіть webfont-файли у `assets/fonts/`, після чого замініть URL у `index.html` на локальний `@font-face` у `styles.css`.


## Важливо для поточної структури SiteData
Тиждень у SiteData зберігати не потрібно. Сайт сам визначає поточний календарний тиждень з понеділка по неділю. Обовʼязкові колонки CSV: `metric_id`, `label`, `percent`, `answer`, `sort_order`.
